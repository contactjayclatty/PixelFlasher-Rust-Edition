Commands that inspect. They do not flash.

Device writes stay in the desktop review flow. These flags read files and catalogs.

PowerShell.\PixelFlasher.exe --inspect .\images\init_boot.img
.\PixelFlasher.exe --process .\firmware\factory-image.zip
.\PixelFlasher.exe --library
.\PixelFlasher.exe --import-legacy .\PixelFlasher4.db
.\PixelFlasher.exe --catalog factory --acknowledge-google-terms
.\PixelFlasher.exe --catalog ota --acknowledge-google-terms
FlagIt doesIt does not
--inspectRead image metadataFlash the image
--processProcess a supported firmware archiveAccept an incremental OTA
--libraryShow the local libraryTalk to a device
--import-legacyImport a legacy BOOT database, read-onlyModify that database
--catalogFetch stable Factory or Full OTA metadata after you acknowledge Google's termsDownload firmware, or contact a device

Optional local MCP is off unless you enable it in Settings. It cannot run a device operation, a shell, or read secrets. MCP contract.

Build from source

Rungit clone https://github.com/contactjayclatty/PixelFlasher-Rust-Edition.git
cd PixelFlasher-Rust-Edition
cargo run -j 2
Checkscargo fmt --all --check
cargo test --locked --workspace -j 2
cargo clippy --locked --workspace --all-targets -j 2 -- -D warnings
cargo build --locked --workspace --release -j 2

Windows CI is not device evidence. Packaging rules: docs/RELEASING.md.

When something looks wrong

What you seeWhat to check
Scan finds nothingSettings points at a folder with both adb.exe and fastboot.exe. The app does not scan at startup. The phone has to already be in the mode that task needs.
The catalog stays emptyYou have not acknowledged Google's terms, or you expected a beta, canary, or watch catalog.
A file or root package is refusedIncremental OTAs are rejected. Live boot accepts boot images only. Root adapters reject versions they do not pin.
Settings or images vanishedData is per directory. Another PIXELFLASHER_DATA_DIR is another library.
You expected the Python appThis build never starts it. See coverage.
